# Sidekick 1.0까지의 개발 진행 상황

## 1. 기록 범위와 용어

- 기간: 2026년 11월 2~3일, 한국 시간.
- 시작점: 개발 AI가 사용자 PC의 Blender를 직접 조작할 수 있는지 확인한 작업.
- 종료점: Qwen3-VL 8B Instruct 전환, 구버전 정리, 핵심 기능 확인 완료.
- 제외 범위: 사용자의 ‘클릭, 입력, 저장 같은 작업을 할수 있는 1.1을 만들어줘’ 요청 이후 개발.
- 개발 AI: 사용자와 이 대화에서 프로그램을 제작한 AI.
- Sidekick: 제작한 PC 프로그램 및 그 안에서 응답하는 로컬 AI.
- 구분 필요 사항: 개발 AI의 PC 조작 성공과 Sidekick의 자체 조작 성공은 서로 다른 결과.
- 버전 체계: v0.1~v0.9는 당시 보관·정리 자료 기준. 1.0은 8B 기반 초기 실행본 완성 단계를 지칭.
- 확인되지 않은 사항: 1.0 당시 소스 전체를 보존한 Git 태그 또는 독립 릴리스의 존재.

## 2. 최초 목표 및 Blender 사전 점검

- 사용자 최초 요청: 바탕화면의 Blender 실행 및 다양한 조작 가능 여부 확인.
- 작업 조건: 기존 작업 파일을 변경하지 않고 새 테스트 장면 사용.
- 당시 개발 AI가 확인했다고 보고한 항목:
  - Blender 5.2.3 LTS 실행.
  - 기본 큐브 선택.
  - G 입력을 통한 X축 3m 이동.
  - R 입력을 통한 Z축 45도 회전.
  - S 입력을 통한 전체 축 2배 확대.
  - UV 구체 추가.
  - 축 기즈모 클릭 및 숫자패드를 통한 시점 변경.
  - 새 `.blend` 파일 저장.
- 확인한 제약:
  - 기즈모 드래그는 두 번 시도했으나 회전 확인 실패.
  - 일부 복합 단축키의 동작 불안정.
  - 메뉴 클릭·개별 키 입력으로 대체 진행.
- 이 단계에서 확인하지 않은 항목: 복잡한 모델링, 재질, 렌더링.
- 후속 사용자 요구: 작업 화면을 보면서 대화하고, 느리더라도 직접 조작하는 협업 도구 제작.
- 초기 상호작용 방식: 작은 텍스트 창을 통한 의견·요구 사항 교환 우선.

## 3. v0.1 — 초기 API 기반 협업 창

- 구현 내용:
  - PC에서 실행하는 작은 대화창 구성.
  - 메시지 전송 시 선택한 화면을 확인하는 흐름 구성.
  - 화면 공유 영역 선택.
  - Blender 연결 기능 구성.
  - 선택·이동·회전·크기 변경·도형 추가 요청 전달.
  - 기존 작업과 구분되는 테스트 Blender 창 사용.
- 당시 개발 AI의 검증 보고:
  - Blender 기본 조작 5종과 대화 도구 간 연결 시험 통과.
  - 작은 협업 창 실행 확인.
- 실제 AI 연결 제약:
  - API 키가 준비되지 않아 실제 유료 API 호출과 화면 전송은 미실시.
  - 도구 간 연결 성공을 실제 API 모델의 지시 이해 성공으로 볼 수 없음.
  - 이 대화의 개발 AI와 별개의 AI 세션을 사용하는 구조.
- 보존 상태: 원본 실행 코드 미보존. 동일 파일의 반복 수정으로 덮어쓰기됨.

## 4. v0.2 — 한글 입력 문제 대응

- 사용자 보고:
  - ‘한글이 안써저’.
  - 영어만 입력되고 한글로 전환되지 않는 증상.
- 수정 내용:
  - Windows 한글 입력기 연결 처리 보강.
  - ‘한글 입력’ 버튼 추가.
  - 입력창 관련 처리 보완.
  - 기존 입력 내용을 유지하는 방향으로 새 창 실행.
- 확인 결과:
  - 당시 개발 AI는 Windows 입력기 연결 테스트 통과를 보고.
  - 실제 사용자 키보드의 한글 조합까지 확인됐다는 보고는 해당 완료 응답에 없음.
- 한계: 입력기 연결 시험 통과와 실제 물리 키보드 조합 성공을 구분해야 함.
- 보존 상태: 원본 실행본 미보존.

## 5. v0.3 — 현재 AI 채팅과의 반자동 연결

- 사용자 요구:
  - 별도 API 키 없이 현재 대화 중인 개발 AI를 Sidekick에 연결.
  - 결과가 약하거나 방식이 단순해도 연결 가능 여부 우선 확인.
- 구현 흐름:
  - 사용자가 Sidekick에서 메시지 전송.
  - 사용자가 현재 개발 채팅에 ‘Sidekick 확인해 줘’라고 알림.
  - 개발 AI가 요청과 공유 화면 확인.
  - 답변 또는 Blender 동작 결과를 Sidekick으로 반환.
- 당시 보고된 시험:
  - 메시지 전달.
  - 답변 표시.
  - 조작 전달.
  - 취소.
  - 같은 답변의 중복 적용 방지.
- 제약:
  - Sidekick이 현재 개발 AI를 자동 호출하는 구조는 아님.
  - 사용자의 별도 알림이 필요한 반자동 방식.
  - 상시 연결·완전 자동 응답으로 해석하면 안 됨.
- 다음 방향 전환: 특정 개발 AI 연결보다 Sidekick의 독립 실행을 우선하기로 결정.
- 보존 상태: 원본 실행본 미보존.

## 6. v0.4 — 독립 로컬 AI 연결

- 사용자 요구: ‘로컬 ai로 독립적으로 작동하게 해줘’.
- 당시 확인한 PC 조건:
  - RAM 약 32GB.
  - Intel Arc 내장 그래픽.
  - 초기 모델 시험은 CPU 실행으로 진행.
- 도입 구성:
  - 로컬 실행 도구: Ollama.
  - 초기 모델 계열: Qwen3-VL 2B.
  - 대화·조작 판단·이미지 해석을 PC 안에서 처리.
  - 로컬 연결 실패 시 외부 AI로 자동 전환하지 않도록 설정.
- 첫 모델 선택에서 발생한 문제:
  - 답변 전에 긴 추론을 생성.
  - 실제 답변을 완성하기 전에 응답 길이 한도 도달.
- 대응:
  - 같은 계열의 2B Instruct 즉답형 모델로 전환.
  - 화면은 선택 영역의 정지 이미지로 전달.
- 당시 개발 AI가 보고한 실제 시험:
  - ‘Cube를 X축으로 2만큼 옮겨 줘’ 요청을 동작으로 변환.
  - 테스트 Blender에서 큐브 이동 확인.
  - 해당 텍스트 요청 처리 약 4.5초.
  - 테스트 이미지의 한국어 설명 약 33초.
- 사용 방식 변화:
  - 별도 API 키 불필요.
  - 현재 개발 채팅에 매번 확인 요청할 필요 제거.
- 모델 학습 상태 설명:
  - 설치 모델은 이미 사전학습된 모델.
  - 사용자 또는 Blender 작업에 대한 별도 가중치 학습은 진행하지 않음.
- 보존 상태: 원본 실행본 미보존.

## 7. v0.5 — 기억 기능 및 반복 응답 보완

- 추가 요구:
  - 취향·작업 기록을 저장하고 다음 실행에서도 참고.
  - 기억 확인·수정·삭제 지원.
- 사용자 보고 문제:
  - ‘잘 작동되니?’에 ‘잘 작동되니?’로 응답.
  - ‘따라하는데?’에도 이전 질문 반복.
  - 질문을 답하지 않고 문장을 약간 고치는 응답 발생.
  - ‘a 라고 해봐’에 요청 문장 전체를 반환.
- 당시 재현 방식:
  - 같은 모델에 조작용 구조화 응답 방식과 일반 대화 방식을 각각 적용.
  - 현재 방식에서는 질문 반복, 일반 대화 방식에서는 정상적인 짧은 답변이 나왔다고 개발 AI가 보고.
- 원인 판단:
  - 조작용 응답 형식을 일반 대화 전체에도 적용한 점을 원인으로 추정.
  - 모든 반복 응답의 단일 원인이 입증됐다는 뜻은 아님.
- 수정 내용:
  - 일반 대화와 Blender 조작 요청의 처리 경로 분리.
  - 취향 메모 저장.
  - 대화·작업 결과 기록 저장.
  - 기억 관리 화면에서 확인·수정·삭제.
  - 앱이 확실히 아는 모델 상태 등의 정보를 잘못 설명하지 않도록 보완.
- 당시 보고된 검증:
  - 기억 저장·재실행 후 불러오기·수정·삭제 시험 통과.
  - 저장된 로우폴리 스타일 선호를 실제 모델이 참고해 답변.
  - 사용자가 제공한 여섯 문장 재시험.
- 남은 문제:
  - 그대로 복사하는 현상은 줄었지만 부정확한 답변은 계속 발생.
  - 기억 저장과 대화 참고 기능이며 모델 가중치의 자동 학습은 아님.
- 보존 상태: 원본 실행본 미보존.

## 8. v0.6 — 노트북 범용 도우미로 확대

- 사용자 요구: Blender 이외의 노트북 사용 상황에서도 활용.
- 사용자가 선택한 우선순위: 화면 설명·대화부터 안정화한 뒤 조작 확대.
- 구현 내용:
  - 일반 도움.
  - 화면 설명.
  - 글쓰기·번역.
  - 문제 해결.
  - 복사한 텍스트 가져오기와 답변 복사.
  - 기존 기억 기능 유지.
  - Blender 조작은 별도 모드로 분리.
  - 화면 변화 감지 및 동일 화면에서 자동 의견 반복 방지.
- 검증 도중 발견한 문제:
  - ‘보내 달라’는 요청을 ‘보내겠다’는 약속으로 변경.
  - 문장 다듬기 과정에서 원문의 주체·의도 변형.
- 대응:
  - 원문의 의미와 주체를 유지하도록 지침·처리 보강.
- 당시 개발 AI의 검증 보고:
  - 번역.
  - 문장 다듬기.
  - Blender와 무관한 오류 화면의 숫자 읽기.
  - 화면이 그대로일 때 같은 자동 의견을 반복하지 않는 동작.
- 지원 범위 제한: 일반 앱의 자유로운 클릭·입력은 이 단계에서 추가하지 않음.
- 남은 문제: 사용자·AI 지칭과 문장 속 행동 주체 혼동.

## 9. v0.7 — 사용자·AI 및 요청 주체 구분 보완

- 사용자 제공 사례:
  - 사용자에 대해 묻자 Sidekick이 자신의 정체성을 설명.
  - 현재 사용자를 Sidekick이라고 설명.
  - 사용자의 정정 이후에도 비슷한 자기소개 반복.
  - ‘네가 이해하지 못하면 나에게 질문해 달라’는 요청을 사용자가 모르는 것을 질문하라는 뜻으로 해석.
- 수정 내용:
  - 사용자 발화의 ‘나·내’와 ‘너’ 지칭 구분 기준 추가.
  - 사용자 정보는 사용자가 직접 저장한 메모를 근거로 처리.
  - AI의 과거 답변을 사용자에 대한 사실로 취급하지 않도록 보완.
  - AI가 이해하지 못한 부분은 사용자에게 확인하도록 요청 해석 보강.
  - 해당 요청을 대화 선호로 저장하는 흐름 추가.
- 당시 개발 AI 보고: 제공된 사례 시험 통과.
- 남아 있는 검증 스크립트:
  - 책을 준 사람과 받은 사람 구별.
  - 자료를 보내 달라고 요청한 사람과 실제 보낼 사람 구별.
- 근거 해석:
  - 스크립트 존재 자체가 모든 시험의 성공 기록을 의미하지는 않음.
  - 특정 문장 감지와 정해진 답변 처리도 일부 사용했다고 개발 AI가 이후 설명.
  - 알려진 사례 보완을 모델의 전반적 이해력 향상으로 해석할 수 없음.

## 10. v0.8 — 가설·확인 및 최신 정정 반영

- 사용자 제공 후속 사례:
  - ‘너는 누구야’와 ‘나는 누구야’에 동일한 안내 답변.
  - ‘이해하지 못하면 질문해 달라’는 요청에 추측하지 않겠다고 응답.
  - 사용자가 가설을 세우고 맞는지 확인하는 것도 중요하다고 정정.
  - Sidekick은 정정 후에도 ‘추측하지 않고’라는 이전 지침 반복.
- 확인한 문제:
  - 불확실한 내용을 단정하지 말라는 지침과 가설 자체를 금지하는 지침의 혼동.
  - 최신 사용자 의견보다 오래된 AI 답변을 재참고.
- 수정 내용:
  - 잠정 가설과 사실 단정 구분.
  - 가설임을 밝히고 사용자에게 확인하도록 대화 선호 수정.
  - 최신 대화 선호 우선 적용.
  - 오래된 상충 답변이 새 지침처럼 재사용되지 않도록 제외 처리.
  - 자기 정체성 질문과 사용자 정체성 질문의 답변 분리.
- 수정 중 재발:
  - 저장 기능 수정 후에도 실제 모델이 오래된 ‘추측 금지’ 답변에 다시 끌려가는 현상 확인.
  - 충돌하는 이전 답변을 걸러내고 현재 선호 전달을 추가 보강.
- 당시 개발 AI 보고:
  - 실제 로컬 모델이 수정된 대화 방식을 설명하는 것을 확인.
- 남은 한계:
  - 특정 오류 처리와 프롬프트·맥락 구성을 보완한 단계.
  - 모델의 전반적 추론 능력을 재학습한 결과가 아님.
- 버전 정리 작업:
  - v0.1~v0.7은 변경 기록만 보관.
  - 당시 v0.8 실행본과 기억 데이터를 별도 복사.
  - 바탕화면 버전 모음·실행·Blender 테스트 바로가기 정리.
  - 이후 8B 전환 시 구버전 정리 수행.

## 11. v0.9 — 답변 중단 및 반복 생성 대응

- 사용자 보고: 답변을 완성하지 못하는 경우가 자주 발생.
- 당시 기록에서 확인했다고 보고한 원인:
  - 900토큰 출력 한도까지 생성된 사례 존재.
  - 한도 도달 시 이미 생성된 답변까지 모두 버리고 오류로 표시하는 코드 동작.
  - 반복 생성 문제 동반.
- 당시 메모리 측정:
  - 전체 RAM 약 31.5GB.
  - 여유 RAM 약 8.5GB.
  - 해당 오류를 RAM 부족으로 단정할 근거는 부족하다고 판단.
- 수정 내용:
  - 길이 제한에 도달한 일반 답변의 앞부분 보존.
  - 일반 답변은 한 번 이어 쓰기.
  - 빈 답변 및 불완전한 응답에 대한 제한적 재시도.
  - 반복 답변 감지·정리.
  - 불완전한 Blender 조작 응답은 실행하지 않음.
- 검증 관련 자료:
  - 첫 응답의 출력 한도를 인위적으로 20토큰으로 제한하는 실제 모델 시험 스크립트 보존.
  - 두 번째 요청으로 이어 쓰고 앞부분을 잃지 않는지 검사하도록 구성.
  - 현재 확인한 자료에서는 해당 스크립트의 별도 실행 결과 파일은 확보하지 않음.
- 사용 모델: 이 수정 시점에는 기존 작은 모델 유지.
- 남은 문제: 응답 복구와 메모리 최적화만으로 기반 모델의 이해력 한계를 해결할 수 없음.

## 12. 모델 확대 및 저장 공간 관련 검토

- 사용자가 검토한 대안:
  - 더 큰 로컬 모델.
  - 외장 GPU.
  - 별도 AI 실행용 PC.
  - RAM 증설.
  - USB·외장 SSD 보관.
- 실제 진행 범위:
  - 장비 구매·설치 완료 기록은 이 범위에서 없음.
  - 4B 모델은 대안으로 안내됐으나 최종 8B 선택 이전 설치됐다고 확인되지 않음.
  - USB는 모델 보관 공간으로 사용할 수 있지만 실행 RAM을 대신하지 않는다고 설명.
- 당시 저장 공간 점검 보고:
  - 관련 파일 합계 약 7.15GB.
  - 모델들 약 3.56GB.
  - 실행 도구 약 2.10GB.
  - 다운로드 압축파일 약 1.49GB.
  - C드라이브 여유 약 427GB.
- 수치 해석:
  - 위 저장량은 8B 설치 이전의 한 시점 측정.
  - RAM 사용량이나 현재 설치 크기와 다름.
  - 이후 모델 교체·압축파일 정리로 변경됨.

## 14. 8B 실제 응답 및 수정 기록

- 주체 구분 1차 사례:
  - 요청: 지민이 하린에게 파일을 보내 달라고 부탁했을 때 실제 보낼 사람 질문.
  - 응답: 하린을 선택.
  - 불필요한 가설 확인 문구가 함께 붙음.
  - 기록 시간: 44.6초.
- 번역 사례:
  - 요청: ‘안녕하세요’를 영어로 번역.
  - 응답: `Hello.`
  - 기록 시간: 3.3초.
- 문장 다듬기 1차 사례:
  - 요청: ‘자료 오늘 보내 줘’를 상대에게 부탁하는 문장으로 수정.
  - 문제: 요청한 문장 대신 사용자 의도를 설명하고 불필요한 확인 요청을 덧붙임.
  - 기록 시간: 30.9초.
- 대응:
  - 가설 확인 지침이 문장 결과만 필요한 작업에 과하게 개입하는 문제 조정.
  - 지침 우선순위 정리 후 같은 문장 재시험.
- 문장 다듬기 재시험:
  - 응답: ‘오늘 자료를 보내 주시면 감사하겠습니다.’
  - 기록 시간: 26.3초.
  - 이후 사용자가 공손한 문장은 평가 우선순위에서 제외하도록 지시.
- 오류 화면 읽기:
  - `ERROR 503` 인식.
  - 기록 시간: 99.7초.
  - 단일 테스트 이미지 사례. 모든 화면의 인식 성능을 보장하지 않음.

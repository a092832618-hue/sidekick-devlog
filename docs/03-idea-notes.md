# 초기 아이디어 노트 — 우리가 만들고 싶었던 것

완성된 기능 목록이 아니라 **1.0에 이르기까지 방향을 바꾼 질문들**이다.

## “작업 화면 옆에서 계속 얘기하면 안 될까?”

작업을 멈추고 긴 채팅창으로 옮겨 다니기보다, 작은 창으로 의견을 주고받고 싶었다. 화면 참고와 대화가 하나의 흐름이면 좋겠다는 생각에서 시작했다.

**남은 기준:** 사용자가 AI를 사용하기 위해 본래 작업을 너무 많이 멈추지 않아야 한다.

## “꼭 별도 API 키가 있어야 할까?”

현재 AI 채팅과 반자동으로 연결하는 시도에서, PC 안의 로컬 모델로 독립 실행하는 방향으로 옮겼다.

**남은 기준:** 연결 방식과 실제로 가능한 일을 정확하게 설명한다. 반자동 중계를 상시 연결이라고 부르지 않는다.

## “Blender 말고 다른 일을 할 때도 쓰자.”

특정 프로그램을 위한 도우미에서 문서·공부·웹페이지·오류 화면을 함께 살펴보는 도우미로 범위를 넓혔다.

**남은 기준:** 범용성이 넓어져도 대화와 화면 설명부터 안정화한다. 할 수 없는 조작을 할 수 있다고 말하지 않는다.

## “사용자에 대해 기억하면 대화가 나아질까?”

취향과 이전 대화를 저장해 다음 응답에 참고하도록 했다. 하지만 오래된 잘못된 답까지 다시 참고하면 같은 오해가 되풀이될 수 있었다.

**남은 기준:** 기억의 양뿐 아니라 누구의 말인지, 언제 정정됐는지, 현재 요청과 충돌하는지를 다룬다. 저장과 모델 재학습을 구별한다.

## “모르면 질문해 줘. 가설도 세워 보고.”

무조건 추측을 금지하는 답은 원하는 대화가 아니었다. 이해한 부분과 불확실한 부분을 나누고, 가능한 해석을 확인받는 쪽을 원했다.

**남은 기준:** “제가 이해한 뜻은 이런데 맞나요?”처럼 가설을 확인한다. 단정과 질문 사이의 중간 단계를 만든다.

## “더 큰 모델을 쓰면 다 해결될까?”

2B에서 8B로 바꾸고 일부 사례를 확인했다. 동시에 응답 속도와 실행 자원에 대한 부담도 고민했다.

**남은 기준:** 모델 크기만으로 성과를 말하지 않는다. 질문에 제대로 답했는지와 기다린 시간을 함께 확인한다.

---

이 기준들이 모두 1.0에서 완벽히 구현됐다는 뜻은 아니다. 당시 시행착오를 통해 정리한 요구와 개선 방향이다.
